## 3. What was established (all merged, PRs #43-#61)

**The reverse leg is air-limited, and that is now measured three independent ways.**

* Forward leg: **exactly 0 air bit errors** across ~37,400 frames, twice. Reverse leg: **~32 err/frame**
  (damage 0.27) attended on 09-27, and **chance level** (0.49, same as the positive control) unattended
  on 09-28 with a reset storm of >16,500 per dwell. Forward held 0 resets throughout.
* Ruled out as causes, by measurement not argument: **carrier tracking** (the capture with the
  textbook-healthy estimate had the WORSE PER), **signal level** (normal 32-33 dBFS in both captures),
  **the delivery plane** (the PHY-only measurement contains none of it and still shows the damage).
* **Retracted:** my own reading that the singles/doubles loss shape localised the episodes to the
  delivery plane. Analogy lost to measurement.
* Availability: reverse leg degraded **15-22 % of the time** against forward **0.08-0.15 %**, over 10
  days of sentinel samples with rig-work windows excluded.

**The RX-only image's "byte-plane defect" is not established.**

* The pad suspect is **falsified in simulation**. Gate 1's driver holds `byte_rx_ready` high, so the
  pad depth is unobservable there **by construction** -- my first clean 2x2 was a tautology.
* **Real finding: no Gate 1 leg exercises the byte-plane handshake at all**, so a wrong ready pad would
  ship undetected.
* Under a new backpressure driver, depths 2-3 are clean and 4-5 lose ~50 %. **But depth 4 has zero
  margin** (1 low cycle in 16 costs 49 %) while the product runs depth 4 at 0.005 % PER -- so the
  harness's latency is not the shipped image's and **it cannot adjudicate production's depth. Do NOT
  add a backpressure gate leg until that is reconciled.**
* The 09-25 hardware verdict is **confounded**: in the same run the reverse ROM phase carried **45,683
  bit errors** against the forward's **0**, and `lost=0` counts DETECTED frames, not correct ones. At
  0.25 %/bit no frame can pass CRC, which is exactly the observed `aligned=0` of 22,973.

**The r4 (2-sps) LO plan is per-rung now**, r2/r3 unchanged, r4 at +60k/+80k. The interleaved sweep
confirmed the LO controls dead-zone proximity (48.9/5.2/41.6/6.2 % alternating with the cell) but

## 5. Traps worth carrying forward

* `tools/check_paths.sh` scans **tracked** files, so running it before `git add` gives a false pass.
  That briefly left master failing.
* The sentinel's four counters are **two per board**: `rate`/`tx` are 148's, `rev`/`rtx` are 146's, and
  148's TX feeds the REVERSE leg. Pairing a board's rx with its own tx is NOT a delivery ratio. Use
  `ops/sentinel_stats.py`.
* Selecting samples with a truthiness test drops legs delivering **exactly zero** -- the worst ones.
* A memory that names a file is not evidence the file exists: `rom_air_ber.sh` had been retired and I
  cited it as available in merged evidence before checking.
* Restarting the trigger unit used to reset its cooldown and cause an extra unattended capture; it is
  persisted now, but **seed `.last_fire` before restarting** if the last fire matters.
