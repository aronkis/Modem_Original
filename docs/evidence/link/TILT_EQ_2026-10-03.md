# Receiver in-band tilt corrector (TiltEq) -- implementation evidence

Design: `docs/superpowers/specs/2026-10-03-rx-tilt-equaliser-design.md`. Plan: `docs/superpowers/plans/2026-10-03-rx-tilt-equaliser.md`.
Motivation and the tolerance curve it is sized against: `FORWARD_LINK_2026-10-01.md` §9 and §11.

## 1. What was built (desk, 2026-10-03)

| piece | where | what |
|---|---|---|
| corrector block | `modem/dev/simulink/tilt_eq_overlay.m` | `QPSK Rx/TiltEq`: three cascaded complex one-pole stages `y[n] = x[n] − a_k·j·y[n−1]` between the receiver input and the AGC; coefficients sfix16_En15 clamped to ±0.95, state sfix18_En14, output saturated to the AGC's sfix16_En14; `en = 0` or `a_k = 0` is an exact pass-through (`y == x`) |
| registers | `modem/regmap/regmap.toml` `[fixes.TILTEQ]`, `modem/dev/hdlcoder/patch_hdlworkflow_tilteq.m` | 0x260 `tilt_eq_a12` `{a2[31:16] a1[15:0]}`, 0x264 `tilt_eq_a3en` `{en[31] a3[15:0]}`, AXI4-Lite write words threaded down like the loop-gain registers; cleared by the 0x000 soft reset |
| assemble hook | `assemble_jupiter_240k5_byte.m` | applied after `loop_gain_axi_overlay`, LEAN only, `QPSK_TILT_EQ_OVERLAY=0` skips; gate(j) asserts block + inports + workflow mapping |
| solver | `ops/tilt_eq_solve.py` | tilt dB → stage count (1/2/3 at 7/14 dB) → a_k by the sim driver's bisection, channel sign → the two words; `--env` form for the sim legs |
| host rail | `ops/tilt_eq.sh`, bring-up hook `QPSK_TILT_EQ=1` in `bringup_r2r3.sh` | 262k-sample Tap-A capture → `tilt_score.py` → solve → write via direct_reg_access → read back → re-measure; writes zeros below 3 dB; `--off`, `--dry` |
| sim | `sim_sro_perturb.cpp` `PERT_EQ_AUTO/A1-3/MISSET`, wrappers `HAVE_TILT_EQ`, `perturb_score.py --tilt-budget`, `modem/gates/tilt_eq.legs` | identity row (bit-identical to the sp3clamp004 f1536 decode, reference `carrier_lock_bank/tilt_eq_c004_baseline_f1536_cols1_10.txt`), tilt rows −8/−12/−16/+10 dB with the inverse set, a +20 % mis-set row, and replays of the recorded 46 % (−14.6 dB, 10-02) and 2.4 % (−10.5 dB, 10-01) days |

Budget pinned by the legs (from §11): every frame from 8 syncs, |median coarse estimate| < 30 units, median |Δcfc| < 200; the live replays use a 95 % sync floor because the recorded signal carries noise.

Tests: `ops/tests/test_tilt_eq_solve.py`, `test_tilt_eq_overlay.py`, `test_tilt_eq_legs.py`, `test_tilt_eq_sh.py`, `test_perturb_score.py::test_tilt_budget_verdict`.

## 2. Regen + Gate 1 (sp3tilteq, 2026-10-03/04)

Regen on nemo (MATLAB R2025b, HDL Coder), `build_image.sh --tag sp3tilteq --tree dev` at the f1536 / 4 sps rung.
Two assemble attempts failed on the new overlay and were fixed in place: the AGC is a library-linked block that a
depth-1 `find_system` by Name does not see (lookup is now by block path), and HDL Coder rejects a MATLAB Function
output assigned from two branches with different fimaths (one `fimath` is now used on every `fi()`). Attempt 3:
`BUILD_HDL_KIT_OK`, `MODEL_OVERLAYS_OK`, gate(j) `TILTEQ regs 0x260/0x264 present + mapped`; the generated
`TxRxCompo_ip_src_TiltEq.v` has the six multipliers (3 stages × 2) and the AXI decoder carries
`write_tilt_eq_a12` / `write_tilt_eq_a3en`.

**Gate 1** (`model_matrix_f1536.legs`, 10 h 27 min): **45 pass / 8 fail**. The eight (`census_clean census_grid
edge_m10 G4_prearm gateA_m10 gateA_p000 repro_p000 words191_k1536`) are a strict subset of the 18 the shipped
sp3clamp004 tree failed on the same matrix (pre-declared / geometry classes, `CARRIER_LOCK_LATCH_2026-09-29.md`
§9); no new failure, ten rows that failed then pass now. `tilt_eq.legs` (identity against the banked sp3clamp004
decode, tilt rows, mis-set row, live replays) -- see §2.1.

For scale, the SAME bank rows without the corrector (§11 of FORWARD_LINK) read bias −472 / −2,401 / −11,321 /
+1,331 and noise 418 / 927 / 1,769 / 684, with 106/112 syncs at −16 dB. With the corrector set from the slope,
every bank point is indistinguishable from the flat channel (tilt 0: bias −10, noise 2), and a 20 % error in the
coefficient costs only noise 2 → 20.

**The live replays are the result that matters.** The two recorded captures are the actual receiver input of the
two bad days. The live forward plan sits at +20 kHz, so a healthy estimate is ≈ −3,400 units (IQR ~33), not 0; the
replay criterion is therefore |median − (−3,400)| < 300 with noise < 200 and ≥ 95 % syncs. On the 46 % day the
live receiver read −11,817 with IQR 4,034 and detected 1,073 of 1,217 f/s; the same samples through the corrected
receiver give **every frame synced, the estimate back on the plan (−3,459) and noise 159**. The 2.4 % day
(−10.5 dB) comes back to −3,391 / 70. (Corrector-off replays of the same files for the side-by-side: §2.2.)

## 3. Gate 2 (sp3tilteq e79f436ae88a, Vivado on hdl-dev-2, 2026-10-04 04:34-06:xx)

`BUILD_IMAGE_WNS_OK wns=0.109 floor=0.005` on the gate clock `axi_adrv9001_adc_1_clk` (88,621 endpoints, 0
failing). **The floor passes but the plan's "≥ current" criterion does not:** the shipped sp3clamp004 image reads
1.187 ns on the same row, and the ten worst paths of the new image all run through `u_TiltEq` (coefficient
register → word decode + clamp → multiply → add → saturate → the stage state or the AGC's input register, slack
0.109-0.235 ns). The modem blocks the paths report tracks are untouched (Symbol_Synchronizer worst slack 2.877,
Carrier_Synchronizer 2.882). Image banked as `images/BOOT.BIN.jupiter.sp3tilteq.e79f436ae88a…` for the functional
gates; it is **not** a Gate 3 candidate with 0.1 ns of slack. Fix applied to the overlay (coefficients decoded and
clamped into registers one cycle ahead, so the data path is multiply + add + saturate only) → second regen
`sp3tilteq2`, see §3.1.

### 3.1 sp3tilteq2 155d09474e30 (registered coefficients, 2026-10-04 05:40-07:xx)

`MODEM_CLK_WNS clock=axi_adrv9001_adc_1_clk wns=0.849 tns=0.0 failing=0 total=88776` -- the TiltEq path went
from 0.109 to **0.849 ns** of slack by moving the word decode and clamp into registers one cycle ahead (the
remaining worst path is the stage state's `isempty` guard register → multiply → state/AGC). 0.849 is above the
sp2A/sp2B references (0.447 / 0.785) and below the sp3clamp004 image's 1.187, which had no block on that path at
all; the budget is adequate for a 61.44 MHz data path and the gate passes with margin. Image banked as
`images/BOOT.BIN.jupiter.sp3tilteq2.155d09474e30…`; this is the Gate 3 candidate once its own Gate 1 and
`tilt_eq.legs` (queued, §2.3) are in.

## 4. Silicon: sp3tilteq2 on 148, forward link (2026-10-04 11:32-14:46)

Operator: "verify on hardware". The reverse leg was still collapsed (146 detecting 440-918 f/s, antennas not yet
re-placed), so every bring-up used `GATE_FPS=400`, and 148's own transmitter was muted for every cell (the 10-02
self-interference class) to measure against the 0.013 % baseline. 148 flashed with sp3tilteq2 155d09474e30; 146
stayed on sp3clamp004. Two rail defects had to be found and fixed before the block could be exercised:

1. **Every cell read 0 f/s, on sp3tilteq2 AND on clamp004** (`hwtilteq_20261004_1132`, probe): 146's watchdog had
   taken its DELIVERY-WEDGE path (reverse half-alive) and relaunched the daemon, which creates a new `tun0` with no
   address, so the rail's traffic generator on 146 had nowhere to send. The fabric detected 1,248 f/s throughout;
   the in-fabric BIST's ~66 errors per 120-bit window is the whitened-payload compare, not a demodulator fault.
   Fix: bring-up records the tun config in `/dev/shm/qpsk_tun.net`, `lock_watchdog.sh relaunch_daemon` re-applies
   it (deployed to both boards by scp; `/root/lock_watchdog.sh` is shipped by `ops/provision.sh`, not bring-up).
2. **Forced coefficients had no effect** (`hwtilteq2_*`, `hwtilteq3_*`: cfc −3,586 / −3,494 unchanged with
   `tilt_eq.sh --set 16`): the capture rail runs a full bring-up at the start of every `-k` leg and its 0x000 soft
   resets clear the write-only words. The write now lives inside the rail at the post-arm poke position
   (`TILT_EQ_SET=off|<dB>|auto`). The words read back 0 by design (HDL Coder write registers, like 0x208).

With both fixed (`hwtilteq4_20261004_1405`, 180 s cells, lost frames in the denominator, cfc from `frames.bin`
over the live window):

| cell | words (written after the arm) | PER | cfc median / IQR / median \|Δ\| | sim prediction (flat bank stimulus) |
|---|---|---|---|---|
| e1 off | 0 / 0 | (control) | **−3,486 / 18 / 11** | — |
| e2 **forced 16 dB** (3 × +0.4509, i.e. a −16 dB slope applied to the flat air signal) | 0x39B639B6 / 0x800039B6 | **84.260 % (4,427/5,254)** before the rail aborted the leg at 17 s (delivery flatline) | **−8,630 / 4,450 / 605** | 9/12 syncs, estimate moved ~6.5k units, noise 3,945 |
| e3 off | 0 / 0 | (control) | −3,471 / 22 / 13 | — |
| e4 **forced 6 dB** (1 × +0.5215) | 0x000042C0 / 0x80000000 | **0.011 % (23/213,578)** | −3,695 / 199 / 119 | 12/12 syncs, estimate moved ~340, noise 239 |
| e5 host-auto (`tilt_eq.sh`: measured −0.39 dB → CLEAN → zeros) | 0 / 0 | **0.006 % (13/216,705)** | −3,493 / 29 / 18 | — |

**Verdict.** The block is live on silicon and host-controllable: a forced 16 dB slope wrecks the link exactly as the
model says (estimate thrown ~5k units off the plan with a 4,450-unit spread, most frames lost), a forced 6 dB
slope is tolerated at baseline PER with the estimator noise rising 11 → 119 (the §11 tolerance curve on the air),
and with the words at zero or host-auto on a flat day the link decodes at 0.006-0.011 %, the pre-move baseline --
the bit-identical pass-through holds on hardware. The sign of the forced-16 estimate shift is opposite to the
bank-stimulus prediction (−5.1k vs +6.5k), which is the spectral-inversion convention between the bank files and
the air; the magnitude and the loss agree. Not shown today: a *benefit* on a tilted day -- the air was flat (−0.2
… −0.4 dB) throughout; that evidence is §2.2's replay of the recorded 46 % day until a tilted day recurs.

`GATE_FPS=400`, both watchdogs restarted with the tun fix, trigger `degtrig-pair-20261004q`. `images/CURRENT.txt`
untouched (rollback = `deploy_image.sh 10.0.0.148 A`).

**Verdict: FAIL on the reverse leg** (`GATE3_VERDICT … long_legs_over_limit=1`); the pair was KEPT on the
candidate. The reverse loss is uniform (no second above 20 bad frames in 600 s, 0 resets), 146's carrier estimate
spread is 1,000-1,370 units (healthy ≈ 33), and the slope 146 sees is **flat** (−0.65 … +0.21 dB across 16 MHz) --
so this is **not** a tilt and the corrector is not its remedy. 146 hears 148 at 37.8 dBFS against 148's 22.3 for
the forward direction: the reverse air path is ~15 dB weaker since the 10-02 antenna move and sits in the
noise-limited regime (§10 of FORWARD_LINK: 20 dB down gave 72 % on the forward leg). The forward leg passes; the
carrier-lock clamp and the corrector do not degrade anything.

**Corrector A/B on the live pair (forward, 180 s, words written inside the rail after its bring-up):**
cell1 off 0.007 % (15/218,601) · cell2 auto 0.008 % (17/214,218) · cell3 off 0.012 % (26/218,612) · cell4 auto 0.006 %
(14/215,877). The host measured 0.08 / −0.14 dB and wrote zeros both times (below the 3 dB floor): on a flat day the
hook is a no-op by design, and the four cells are statistically one population.

**Carrier probe trial (21:01-21:12):** `carrier_probe.sh` chose 2100 MHz (|tilt| 0.07 dB; 2000: 2.42 dB CLEAN;
2150: 7.54 dB MARGINAL), all three at full detection -- consistent with the day's flat air and the table default.
