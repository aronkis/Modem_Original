## The two failing cells, characterised

* Frames are detected at the correct cadence (frame starts every 49,215 descrambled bits); the
  payload symbols are ~75 % mismatched against ALL FOUR QPSK rotations of the golden (random):
  not a slip, not a wrong quadrant -- the carrier is not held (CS output 4th-power phase drifts
  67 rad over 20 ms, std 12.6 rad; constellation 9 % ambiguous vs 0 % on a passing cell).
* Timing loop: 153,539 strobes in 20 ms (= the symbol rate), mu bimodal at the 0/1 boundary
  (52 % in [0,0.1), 30 % in [0.9,1)), 1.5 % of strobes at spacing 1 and 1.5 % at spacing 3,
  TED std 0.117 -- the same picture as the PASSING CFO-0 offset-0 cell (mu boundary, clean
  constellation, 0 % ambiguous). Rate Handle ring: occupancy 0/1, no pop-on-empty after
  acquisition, no push-on-full.
* Coarse estimate 0.00393 of 0.004 applied; the residual is the carrier loop's job.
* A guard that suppressed a strobe on the sample after a strobe (double-underflow at 1/sps = 0.5)
  broke previously passing cells and was reverted (65bc816f): the double strobe is legitimate
  (instants n+0.002 and n+1.999 are one symbol apart).

Open: why the carrier loop loses lock only when the timing phase sits on the sample boundary AND
a carrier offset is present. Candidates: the boundary dither feeding 1.5 % mis-timed symbols into
the PED at a loop bandwidth derived per sample, not per symbol; or an interaction with the
coarse compensator's 4096-sample window. On silicon the timing phase is never pinned to the
boundary (the SRO sweeps it), so this is an acquisition-phase corner, but it must be understood
before the rung ships.

|---|---|---|

| CS output 4th-power phase std | 0.03 rad, 0 % ambiguous | 2-8 rad, 6-8 % ambiguous |

The coarse estimate is right in both (0.00389 / 0.00391 of 0.004) and neither loop resets. The
symbol stream leaving the SYMBOL SYNCHRONIZER is already corrupted in the failing cell (its
4th-power phase cannot even measure the applied CFO), so the carrier loop is fed distorted
symbols and cannot hold; the carrier loop itself is not the defect. In the passing cell the
same stream is clean. The remaining question is therefore in the timing recovery / interpolator
at this one delay class: offset 0 is the only cell where the loopback delay is an integer
number of SYMBOLS (4 bus samples = 1 symbol); the +-0.5 cells (one rail sample) and the +-0.25
cells (half a rail sample) both pass with the same CFO, and offset 0 without CFO passes too.
Next probe: the interpolator's mu and strobe instants against the transmitted symbol instants
in both cells, and the Gardner detector's S-curve bias under a frequency offset at 2 sps.

## Root cause (2026-09-19 11:30): the Rate Handle ring pops stale symbols at occupancy 0

Timing probe (both cells, per 2 ms window): the failing and passing cells are indistinguishable
in every symbol-sync metric (strobe rate and 1/3-spacing counts, mu boundary fraction, TED and
loop-filter statistics). The ONE difference is the Rate Handle ring occupancy: 0.66 mean, 30 %
of beats at 0 (failing) vs 1.17-1.35, 0 % at 0 after acquisition (passing).

Sequence probe (Rate Handle input at strobes vs output at valid, second half of a 16 ms run):

| | passing cell | failing cell |
|---|---|---|
| best alignment lag (symbols) | 1 | 32 = the ring depth |
| output == input at that lag | 100.00 % | 63.7 % |
| mismatching pops | 0 | 22,190 of 61,173 (36 %) |

A pop while the ring is empty returns the slot written 32 symbols earlier (pointer
full/empty ambiguity), so a third of the symbols downstream are ring-stale: random against
every QPSK rotation, carrier loop cannot hold, frames detected but undecodable -- exactly the
observed signature. Why only these cells: at 2 sps the nominal pop cadence (mod-2 counter)
equals the push cadence beat for beat, so the steady-state occupancy is whatever the
acquisition phase leaves it at; a loopback delay of an integer number of symbols leaves it
at 0/1. The R4B EMPTY-edge skip does not help in the sweep window: it arms only after 8
frames of lock and once per 13-slot window.

Fix (rxfix_steer_overlay, sps 2 only): the nominal pop is gated on the one-beat-old
occupancy >= 2 (`RxSteerOccFloor` into the pop AND), which raises the steady-state floor to
1-2 symbols at the cost of one symbol of latency and makes the empty pop impossible. sps 4/8
keep the shipped two-input pop (their cadence leaves the ring at >= 1 by construction; the
34 pop-on-empty events in the f1536 reference table are the same mechanism at a far lower
rate and are a candidate follow-up).

## Occupancy floor verified; the last cell is the zero-SRO "peak on the window's last slot" corner (2026-09-19 16:20)

Re-run on the floor model: CFO +0.004 offset 0 PASS (was FAIL), CFO 0 offset 0 PASS, CFO +0.004
offset +0.5 PASS -- the ring now returns its input at lag 1 (100 %) in every probed cell. Sweep
standing: **22 of 23 cells PASS.**

The remaining cell (CFO -0.004, offset 0) is not a synchroniser fault. Probes on the floor model:

* carrier chain (2 ms windows): coarse estimate -0.0041 (the applied -0.004; the 0x154 telemetry
  tap shows 0 because it saturates a negative estimate -- a reporting bug, follow-up), residual
  +0.00008 cycles/symbol after compensation, carrier loop locked from ~8 ms with PED std 0.02,
  4th-power phase std 0.03 rad, 0 % ambiguous -- identical to the passing half-symbol cell;
* preamble detector: the correlator peaks once per frame at 0.50 against a 0.36 threshold in BOTH
  cells, the one-frame realignment FIFO fills to 24634 and pops per beat in both, BUT Peak Search
  reports the peak at slot **24633 = the last slot of the 24634-slot search window** and never
  raises timingOffsetValid (peak magnitude output stays 0), so Timing Adjust never emits a sync
  pulse and the Packet Controller never starts. In the passing cell the peak sits at slot 4 and
  is reported normally.

With zero sample-rate offset in the loopback the frame-to-window phase never moves, so a start
phase that lands the peak on the window's done slot stays there for ever. On silicon the frame
phase drifts through that slot within a few frames (~16 frames at 2.5 ppm) and, once synchronised,
Timing Adjust re-anchors the window to the detected frame. The stock Peak Search has behaved this
way at every rung (the sim_burst_force `edge` forcing study moved the peak onto the done slot on
purpose); the sps-2 sweep exposes it because the model-time frame is an exact integer number of
symbols at delay 0. Recorded as a documented acquisition-corner exception of the sweep (same
policy as Gate 1's exception set); a Peak Search that reports a last-slot peak is a candidate
robustness follow-up for every rung, not an sp4 blocker.
