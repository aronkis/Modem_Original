# 2-sps rung (f3072, sp4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the deployed 4-sps rung with 2 samples per symbol at the unchanged 61.44 MSPS interface (30.72 Msym/s), carrying a doubled frame (`f3072`) at the unchanged ~1,245 f/s, and gate the resulting single image `sp4` on both legs.

**Architecture:** The rung is a model parameter (`frame_config_k5.m` + `commhdlQPSKTxRxParameters.m`) consumed by `assemble_jupiter_240k5_byte.m` and its overlays; a new frame contract `f3072` in `contract/` is the single source for every geometry number; the build chain (`build_hdl.sh` -> hook -> Vivado template) and the sim gates (`make_sro_trees.sh`, `run_gates.sh`, a regenerated stimulus bank) are re-pointed at the new rung; the host gets an `f3072` mode with a 4 MB DMA carve (new dtb); ops gets rung `r4`. Silicon acceptance is the arm-lottery gate plus 600 s per leg on both legs.

**Tech Stack:** MATLAB R2025b + HDL Coder (`modem/`), Verilator (`modem/rtl_sim`), Vivado 2025.1 on hdl-dev-2, C host (`host/`), bash/python ops, pytest, the repo MATLAB test runner (`tests/runTests.m`).

**Spec:** `docs/superpowers/specs/2026-09-13-2sps-rung-design.md` (amended by Task 1 for the derived frame numbers).

**Revision 2026-09-18 (before execution started).** The repo changed under this plan between 09-15 and 09-17:
the dev/prod split (`modem/dev` overlay source, `modem/prod` DERIVED flattened model, `build_hdl.sh --tree dev|prod`),

  re-derived (`prod/derive/derive.sh`), prod's Gate 1 must equal dev's, and the `sp4` image is built and flashed
  from `--tree prod`. New Task 7b carries this; every re-time round in Task 8 repeats it.
* **One-way images untouched (decision A).** The banked TX-only/RX-only images stay at sps 4 / f1536; the
  `QPSK_ONEWAY` overlay and its scripts keep their f1536 defaults; `frame_config_k5.m` keeps accepting
  sps 4 / f1536 (and 8 / k5) so they remain rebuildable. Nothing sps-4 is deleted in this effort.


## Global Constraints

- Sample rate stays 61.44 MSPS; fabric clock 122.88 MHz; profile `lvds_61p44_fdd_jupiter` unchanged; the one-clock DAC hook (`modem/instruments/txclk`) stays in every kit.
- `f3072` geometry (derived by the contract rules, Task 1): InfoBits 24,580; TailBits 4; CodedBits 49,168; interleave 3,073 x 16; FillerBits 48; PayloadBits 49,216 (769 words, 1,538 ROM words); data symbols 24,608; preamble 26 symbols; frame 24,634 slots; WordsPerPacketRx 382; delivered 3,056 B; TX transfer 6,152 B; `RxPipelineSkipBits` 41 unchanged.
- Rate rung `r4`: `KSYM=30720`, `FPS=1247`, `GATE_FPS = FPS*90/100`; `-r 30720` on the daemons.
- RRC rolloff 0.25, span 8 symbols at 2 sps (17 taps).
- Invariants that must NOT be edited: `49332` samples per frame (12,333 x 4 = 24,666 x 2 is coincidental; the real value is 24,634 x 2 = 49,268 -- see Task 6: every `49332` becomes `49268`, never doubled), `nsamp` in the reference table follows from the new frame, `CAP_OUT_GOLDEN 0x04922282` is geometry-independent.
- Counter widths: any `[13:0]` / `14'd` / `uint16(12333)` tied to slots becomes 15-bit / `uint16(24634)`; `uint8(191)` becomes `uint16(382)`.
- Never `git add -A`; `git commit -s`; "commit" implies push; branch `2sps-rung-2026-09-18` off `master` (created 09-18). One PR per gated milestone (Tasks 1-4 model+chain; 5-7 Gate 0/1 evidence; 7b prod derivation; 8 Gate 2 + banked image; 9-11 host/dtb/ops; 12 silicon evidence), each merged when green (standing instruction).
- Shared MATLAB lives in `modem/common/model/` and is only on the path inside a kit (`make_kit.sh`) or after `addpath(modem/common/model)`; kit scripts call `cd(KITDIR); kitpath(KITDIR)` BEFORE any shared function. Tests that drive MATLAB in batch must `addpath` `modem/common/model` (and `contract/`) themselves.
- `rtl_sim/studies/` benches are provenance and are NOT rewritten for the new geometry (rtl_sim/README policy); only the live top-level benches, `sro_score/`, the `.legs` tables and `ops/tests` are edited.
- Rig rules: flashes under the rails only (`ops/flash/flash_148_txfix.sh` with `GOLD=any`, `flash_146_txfix.sh`; `FLASH_MD5` is resolved through `images/MD5SUMS`, `FLASH_TAG` is recorded only), hold the sentinel with `SENTINEL_STOP` for the duration, never edit a script a live unit runs, long jobs under `systemd-run --user`, no polling faster than 60 s, NEVER a register read or health probe while an arm is in flight (the 148 no-ping hang, five occurrences). Nothing is flashed without the operator's go: Task 12 starts only after check-in.
- Every PER claim: command, sample count, lost frames in the denominator (`ops/accept_analyze.py`).
